# 验收方法

本文件只保留可复用的验收场景，不记录个人平台账号、课程、设备指纹、部署路径、日期或学习统计。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 直接运行部署 | 服务可启动、健康检查成功、配置目录权限正确 |
| AC-02 | Docker 部署 | 兼容架构启动，非 root、只读根文件系统和健康检查有效 |
| AC-03 | 管理认证 | 未登录请求被拒绝，登录、注销和来源校验符合预期 |
| AC-04 | 平台会话 | 登录成功后能独立同步；会话失效时显示可恢复错误 |
| AC-05 | 任务同步 | 分页、时间、状态和未知字段映射经过模拟测试 |
| AC-06 | 通知调度 | 首次通知、去重、静默、紧急例外和重试状态正确 |
| AC-07 | 恢复行为 | 重启或断网后先核验状态，每项有效任务最多补发最近事件 |
| AC-08 | 数据持久化 | 状态、凭据和设置在重启后保留；并发写入不覆盖新数据 |
| AC-09 | 资源观察 | 空闲、同步和通知阶段分别测量，并注明测试条件与限制 |
| AC-10 | 跨架构构建 | 目标 Linux 架构构建成功，产物不包含本地路径或凭据 |

真实平台或设备验收应在本地隔离环境进行。提交前运行 `go test ./...`、`go vet ./...`、前端测试和脚本测试；不得用示例数据推断真实平台能力。
