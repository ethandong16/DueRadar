# 技术设计与实现边界

## 运行结构

单个 Go 进程提供内嵌静态网页和 API；多用户层管理账号、网页登录会话，并将请求路由到各用户的独立工作实例。每个用户有自己的任务状态、平台会话、提醒设置与事件、Bark 配置及后台同步／通知调度。各实例运行 15 分钟同步时钟及 15 秒通知时钟，平台慢请求不阻塞下一轮通知。平台适配器契约分别提供 `Validate(ctx)` 与 `Tasks(ctx)`，避免用任务接口成功代替登录验证。多用户实现仍在进行，隔离、迁移和资源占用均待验收。

`internal/core` 管理统一任务与持久化事件。`internal/vault` 加密平台会话与通知凭据。`internal/bark` 处理 Bark HTTPS JSON 推送，拒绝重定向以避免把密钥转发到另一个地址。`internal/server` 提供认证、设置与独立后台时钟。`internal/platform` 实现雨课堂和知到校内课的官方扫码、身份验证及只读采集。

每个用户的本地 JSON 状态快照按个人规模设计：修改先写 0600 临时文件、同步到磁盘并原子重命名；Linux 上再同步目录。每次提交都复制完整状态，写失败不修改内存状态。同一数据目录应仅运行一个进程。已结束（已发送、失败、取消）的事件保留 180 天，由 15 分钟维护任务清理；待发送事件不受影响。任务记录继续保留，超出该窗口的历史事件不再存储；运行记录页面最多显示最近 200 条，且始终优先包含待发送提醒。多用户总资源占用和写放大须实测；若任务量继续增长，应评估迁移到嵌入式数据库。

入口程序在打开状态或密钥前取得 `.dueradar.lock` 的排他所有权，整个服务生命周期持有句柄。Linux 使用非阻塞 `flock`，Windows 使用禁止共享写入／删除的文件句柄；退出和崩溃均由系统释放。锁文件保留，运行时删除它会破坏所有权约束。同目录的路径别名仍指向同一文件锁；不同数据目录独立运行。健康检查和版本查询不占用数据锁。

## 规则选择

- 作业／考试／章节测试截止：1440、180、30 分钟；考试开始：1440、60 分钟；视频截止：4320、1440、180 分钟。
- 采用需求中的建议默认：Asia/Shanghai、23:00—08:00 静默；允许关闭、修改时区和时间。
- 已完成、未知状态和截止时间未知分别处理；未知状态不产生截止催促。
- 仅已配置的 `exam_start=60` 和截止类 `=30` 提醒享受静默例外。自定义 45 分钟、延后消息或恢复到紧急窗口内的普通提醒不会自动升级成紧急通知，不额外生成时点。
- 考试开始前通知在考试开始后失效；截止催促在截止时失效。
- 重启必须先成功重新同步；同步失败后暂停该平台任务催促，保留故障通知。即使无显式失败，超过 30 分钟未成功同步也暂停任务催促，避免用过期完成状态发送。
- 恢复时每任务最多保留最近一条错过的定时提醒，取消较旧的过期候选；静默延后与恢复复用同一事件标识。
- Bark 最多尝试 6 次，指数退避；每次重试再次检查任务、静默和新鲜度。发送前持久化领取状态，重启后重新核验。

通知发送按到期顺序逐条领取，取消或状态变化不预先占用后续事件的尝试次数。领取后明确尚未调用网络时，可以按原租约与尝试次数归还；归还写入失败则暂停并先重试持久化。已调用网络的超时或取消仍保留一次尝试，因为远端结果可能不确定。

运行状态从持久化事件汇总仍有效的失败记录和最近成功时间，因此重启或同批其他通知成功不会掩盖待重试失败。磁盘写入故障优先显示；原始 Bark 错误不直接进入状态。已完成、已取消或已过期任务的失败提醒不计入待处理故障数，发送历史在 180 天保留期内仍可查看。

网络推送没有端到端 exactly-once 保证：Bark 已接受但进程在记录成功前崩溃，可能重复一条通知。事件生成与正常重启去重已实现；文档不把网络不确定性描述为已解决。

## 个人账号认证与凭据

用户通过个人用户名和密码注册、登录；单实例最多 16 个账号。用户名规范化后唯一，密码以带随机盐的 PBKDF2-SHA256 哈希保存在根目录 `users.json`，不保存明文。网页登录会话使用 256 位随机值、HttpOnly/SameSite=Strict Cookie，15 天过期；会话令牌的哈希及所属用户保存在 `user-sessions.json`，重启后未过期会话仍可使用。公网须经 HTTPS 反向代理并显式设置 `DUERADAR_SECURE_COOKIES=true`。修改请求验证 Origin 与 Host，拒绝跨站 Fetch 请求并要求同源标记；JSON 请求体有大小限制。登录限速按服务看到的来源地址记录失败尝试：15 分钟内出现 10 次失败后，同一地址的后续验证至少间隔 2 秒；该限制在密码校验前执行，正确密码也需等待短暂间隔，但不会永久锁定账号。当请求来自回环、私有网段或 Tailscale（`100.64.0.0/10`）时，应用采用 Cloudflare 的 `CF-Connecting-IP` 作为限速来源，使经隧道访问的不同用户各自拥有独立预算；来自公网地址的直连请求不采信任何转发头，始终使用实际对端地址。限制保存在进程内，重启后重置，公网还需在可信反向代理处配置持久、按真实来源的限速和访问控制。

`DUERADAR_ALLOW_REGISTRATION=false` 在首个账号存在后关闭新注册；没有账号时仍可创建首个账号。当前开发版未设置或留空时允许注册，但默认策略尚在讨论，班级示例显式设置 `true`。开放注册时，任何能访问网页的人都可创建账号直至上限，应控制访问范围。暂不提供删除账号或修改账号凭据的界面。

新注册账号使用随机 ID，状态和凭据位于 `data/users/<随机用户ID>/`，而不是按用户名命名；每个用户分别拥有 `state.json`、`master.key`、`secrets.enc`。Bark Key 和平台会话不进入任务快照和 API 响应。AES-256-GCM 密钥保存在 0600 `master.key`，密文位于 `secrets.enc`。这防止误读密文或错误导出，不抵御已获取设备账户权限的攻击者；备份时保护整个目录。平台会话由程序新建的官方扫码或辅助登录流程取得，并独立验证身份后保存。

### 单用户升级与回滚

旧数据目录的用户注册表不存在时，`DUERADAR_ADMIN_PASSWORD`（至少 12 字节）用于创建初始 `owner` 账号的密码，旧 `state.json`、`master.key` 和 `secrets.enc` 留在数据根目录，由 `owner` 继续使用。全新目录可以留空并由用户注册；若注册表不存在且检测到旧状态或凭据，必须先提供原管理密码。即使是全新目录，在注册表不存在时非空的该变量也会创建 `owner`；注册表存在后，该变量不再修改或重置任何账号密码。若注册表丢失但 `users/` 有内容，程序拒绝启动，以免误认成空安装；首次注册中断留下未登记目录时同样需要人工检查。

升级前停止服务并备份整个数据目录及旧二进制，保留用户注册表、各用户目录和密钥；旧版 DueRadar 网页登录会话不导入，升级后需重新登录。旧平台会话作为根目录凭据保留，但升级后仍需验证。恢复旧版本前，须停止服务并恢复与旧版本匹配的完整数据备份；升级后的新账号及其数据不在旧备份中，回滚时会丢失，应先另存升级后的完整目录。迁移与回滚流程仍待实测，不代表已通过验证。

平台适配器可通过 `Credentials()` 导出验证或采集后的最新会话。服务器保存同步后的会话前检查该次操作的代次和原凭据，事务更新对应字段，防止旧同步覆盖新登录或通知设置。重新绑定失败时不会改写已保存的会话；服务立即排队复核原绑定，避免把提醒暂停到下一轮定时同步。普通雨课堂会话迁移为带版本的 Cookie 快照，保留域、路径和绝对过期时间；导入旧 Cookie 字符串时不虚构已丢失的过期信息。旧程序不识别新格式，回滚须恢复匹配的数据备份。

API 只接受 HTTPS Bark 地址，禁用跳转。更换服务器地址必须重新填写 Key，留空保留只适用于原服务器。

## 真实平台接入验证

按普通雨课堂、知到共享课、知到校内课分别执行：

1. 在电脑通过平台原有扫码或账号密码流程登录，记录验证码与会话过期行为。
2. 单独确认登录验证接口、只读任务接口、分页、任务标识、时间单位／时区、提交状态与视频进度字段。
3. 使用脱敏响应编写映射测试，不推断缺失时间。
4. 将会话通过受保护流程交给 小型 Linux 设备，关闭辅助电脑，再验证独立 HTTP 采集及会话续期。
5. 用平台页面逐项对照任务，然后接入生产同步，最后进行 Bark 到达验收。

雨课堂和知到校内课已完成扫码、独立身份验证、真实分页采集和设备端会话复用。Bark 测试已由用户确认收到。共享课无实际课程样本，密码登录、验证码流程、长时间续期及 24 小时运行仍待验证。一次接口 200、登录页可打开、或模拟测试成功不单独构成平台验收。

每轮同步同时启动雨课堂和知到，各有独立超时，最多两个平台操作并发；单个平台失败不取消另一个平台，也不会耗尽其启动前的等待预算。结果分别记录。重新绑定通过代次检查拒绝旧请求写回，成功保存新会话后排队同步。网页一次只保留一个扫码流程，关闭时等待对应平台的取消请求完成，再允许启动下一次绑定。后台操作共享可取消的服务生命周期；退出同时等待 HTTP 请求与后台保存结束。通知持久化失败在运行状态显示，并暂停后续发送。
